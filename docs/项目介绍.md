# 项目导读：从零读懂这套超快超声仿真

> 面向对象：第一次接触这个项目、想快速搞清楚"它做了什么、代码怎么跑、每个文件为什么这么写"的人。
> 读完这份文档，再去看 `src/` 里的代码，应该能一路顺下来。
> 配套文档：`docs/实验设计方案.md`（怎么做）、`docs/实验报告.md`（结果如何）。

## 1 一句话说明这个项目

用 **Field II** 仿真一条 128 阵元线阵探头，比较三种成像方式：

| 方法 | 一帧发射几次 | 特点 |
|---|---|---|
| 传统逐线聚焦 B 模式 | 128（每条线一次） | 焦点附近最清楚，离开焦点迅速变差 |
| 单平面波 | 1 | 极快，但分辨率、对比度都最差 |
| 相干平面波复合（CPWC） | 11（本实验设定：−10°…+10°，间隔 2°） | 用 n 次发射"合成"出一个发射焦点，接近聚焦图像质量 |

要回答的核心问题：**11 次平面波发射的复合，比单平面波好多少？与逐线聚焦相比如何？代价是什么？**

结论在报告里：囊肿对比度 12.8 → 23.3 dB（强度 dB，10log₁₀）、横向 −6 dB 宽度 0.84 → 0.75 mm、30 mm 处 SNR +8.8 dB；代价是发射 11 次（采集帧率推导值 1167 Hz）。

## 4 数据流：一条平面波是怎么变成一张图的

```
params.m
   │  给出：soundSpeed、sampleRate、阵列、角度、网格、体模、噪声
   ▼
phantom_uniform ──► pos, amp        （2 万个散射子的坐标与幅度）
   │
   ▼
acquire_pw(角度 α) ──► rf [2746×128]  t0     ← Field II 算出的通道数据
   │                        │
   │                        ▼
   │                  das_pw(rf, t0, α, dt)
   │                        │  按延时曲线在 128 个通道上取值、相加
   │                        ▼
   │                  img [1101×256]        ← 一个角度的"射频图像"
   ▼                        │
存盘 data/pw/P1_a###.mat ◄───┘
   │
   │   （11 个角度都做完）
   ▼
stage_analysis: 把某几个角度的 img 直接相加  ← 相干复合，仍在射频域
   │
   ▼
abs(hilbert(...))     ← 取包络（必须在这之后！）
   │
   ▼
20log10(...)          ← 对数压缩到 60 dB
   │
   ▼
figures/F8、F9        ← B 模式图
```

一句话记住：**"发射 → 采集通道 → 逐角度波束形成 → 射频域相加 → 取包络 → 显示"**。
顺序错一步（尤其是"先包络再相加"），复合就退化成非相干平均，横向分辨率不会改善。

## 5 核心算法逐个讲

### 5.1 平面波怎么"倾斜"出去（`acquire_pw.m`）

让每个阵元按一条直线延时发射：

```
d(x1) = x1 · sin(α) / c        （x1 是阵元坐标，可为负）
```

阵元在 x1 处越靠右、角度为正，就发射得越晚，波前因此倾斜 α。E0 里用 40 mm 深度
一排点验证过：峰值到达时刻随 x 的斜率应当等于 sin(α)/c，实测比值 0.98–1.00。

### 5.2 回波怎么"聚"回来（`das_pw.m`）—— 四个时间项

对每个像素 (x, z) 与每个阵元 x1，计算它应当在什么时刻被采样：

| 项 | 表达式 | 物理含义 |
|---|---|---|
| ① 发射 | (z·cosα + x·sinα)/c | 平面波从阵列到散射点 |
| ② 接收 | √(z² + (x−x1)²)/c | 散射点回到阵元 x1 |
| ③ 发射延时补偿 | x1·sinα/c | **Field II 的坑，见 5.2.1** |
| ④ 时间零点 | dt | E0 标定的常数偏移 |

然后把 ①+②+③+④ 换算成采样下标，对 128 个通道做线性插值、加窗（|x1−x| ≤ z/(2F) 的
矩形孔径）并求和。这就是最朴素的延时叠加（DAS）。

**孔径随深度变化**：F 数固定 1.75，所以 30 mm 处用 52 个阵元，60 mm 处用 104 个。
代码里 `hw = z/(2*fNumber)` 与 `m = |elementX-x| <= hw` 就是在做这件事。

#### 5.2.1 必须知道的坑：Field II 把发射延时写进了通道时间轴

`calc_scat_multi` 返回的第 j 通道信号，其时间轴相对绝对时间多了 d(x_j)。
如果 DAS 只用 ①+②，图像会被剪切 Δx = −z·sinα（10° 时约 5.2 mm），单角度图
看起来"像有旁瓣"，11 角度复合则完全散焦。

E0 的判据：逐通道峰值时刻 vs 模型的残差

| 模型 | 残差 RMS |
|---|---|
| ①+② | 1.225 µs |
| ①+②+③ | **0.010 µs** |

所以代码里 ③ 不能省。同理，聚焦发射（`acquire_focused` / `das_focused`）把发射延时
显式算成 (|F| − |F−x1|)/c，再在 DAS 里加回去。

> 如果你以后自己写波束形成：先用**单个点散射子**验证"逐通道峰值时刻 vs 模型"的残差，
> 小于 0.05 µs 才算通过。只看图像"像不像聚焦"是不够的。

### 5.3 相干复合（`stage_analysis.m` 里的 `compound_rf`）

```matlab
rf = zeros(...);
for i = idx            % 该方法的发射序号（PW 只有 1 个，C11 是 1…11）
    rf = rf + load(...).img;    % 直接相加，仍在射频域
end
env = abs(hilbert(rf));         % 相加之后才取包络
```

为什么必须这样：各角度的回波在焦点处同相，相加时信号按 n 倍增长、噪声按 √n 增长，
于是 SNR 提升约 10log₁₀(n)；若先取包络，相位信息丢失，只剩非相干平均，波束不会变窄。

### 5.4 声场与成像区域的均匀性（`stage_fields.m` / `psf_map.m`）

`calc_hp` 给出某角度在网格点上的声压波形，`stage_fields` 把 11 个角度各自的峰值声压
存成 `peakAll`（图 F3/F4）。把这些峰值按角度相加（`sum(peakAll,3)`）就是 DAS 之后图像
实际看到的发射加权 $\sum_\alpha|p_\alpha|$，图 F14(b) 画的就是它：中央一条带是 0 dB
（11 束全照到），向两侧随覆盖束数减少而下降。

**要检验成像区域，不能只看声场，要逐点做一次成像**。`psf_map` 在 $x=\pm10$ mm、
$z=15$–50 mm 的网格上逐点放一个单散射子，每个点都走完整链路（11 个角度发射 →
128 通道 → DAS → 射频域相加 → 包络），得到该点的峰值幅度、相干因子与 −6 dB 宽度，
图 F5 画的就是它：扣除深度趋势后的残差 ±1.01 dB，横向 −6 dB 宽度 0.71–0.78 mm 与
深度无关（逐点测量的结果见报告 5.3）。

**一个曾经的错误做法（已删除，见 `docs/实验报告_讨论与附录.md` 的 B13）**：把 11 个角度的声场按"到轴上某点的
传播时间"平移后相加。它只补掉了轴向相位 $z\cos\alpha/c$，横向相位 $x\sin\alpha/c$
还留着，于是离轴处各角度的脉冲彼此错开、退出叠加，得到一条"看起来像焦斑"的窄条
（宽约 $cT/(2\sin\Delta\alpha)\approx1$ mm）。那不是成像里的任何量：真实成像在 DAS 里
逐像素补掉 $(x\sin\alpha+z\cos\alpha)/c$，加权是幅度相加而不是场的相干相加。

### 5.5 噪声与 SNR（`stage_sigma.m` / `stage_noise.m`）

- 噪声加在**通道域**，每个阵元、每次发射都独立 → 这样"信号相干、噪声不相干"的前提
  才成立，10log₁₀(n) 才可能被观察到。
- σ_e 由"单平面波在 30 mm 处 20 dB SNR"反解：`σ_e = sqrt(Ps / (10^(SNR/10)·W))`，
  其中 W 是波束形成权重平方和（`das_pw` 的第二个输出 w2）。
- 解析噪声公式用 20 次蒙特卡洛验证，比值 0.96（报告表 T-A）。

SNR 定义：`10log10(<s²>/<n²>)`，5×5 mm 滑窗，沿 x 取中位数，再以 30 mm 处的单平面波为 0 dB。

### 5.6 指标定义（`metrics_*.m`）

| 指标 | 怎么算 | 注意 |
|---|---|---|
| 横向分辨率 | 点目标横向包络的 −6 dB 全宽 | 先 8 倍 pchip 上采样再找交叉点，否则被 0.05 mm 网格量化 |
| 轴向分辨率 | 点目标轴向包络的 −6 dB 全宽 | 同上 |
| 对比度 | 10log10(囊内平均强度 / 囊外平均强度) | 强度 = 包络²；内区 r≤2 mm，外区 4–6 mm。强度比取 10log10，与 20log10 的幅度比等价 |
| CNR | \|μout−μin\| / √(σout²+σin²) | 囊一黑就饱和在 0.7，本实验条件下不区分方法 |
| SNR | 见 5.5 | |

**断点续跑**：所有 `data/pw/*`、`data/foc/*`、`data/noise/*` 都是"存在即跳过"。
想重跑某一次发射，删掉对应文件即可。

**但"存在即跳过"有前提**：跳过只在参数没变时成立。采集前会比对
`data/stamp_acq.mat`（`src/data_stamp.m` 给出的 35 个参数 + 采集算法版本）：
一致才续跑；不一致就报错并列出改过的参数，必须用 `run_core('cold')` 重算。
因此改 `P.elemPitch`、`P.angles`、`P.randomSeed` 之类的参数后**不会**把旧数据当成新结果。

**算出来的东西是另一套缓存**：`data/field/maps.mat`（`calc_hp` 算的声场）、
`data/res/psfmap.mat`（逐点成像）与 `data/res/axisres.mat`（轴上逐点单散射子）不是采集，
而是确定性计算。三份文件里各存了一份输入指纹（`src/result_stamp.m`：采集链路的 35 项
参数 + 网格/细网格/`dt` + 计算版本号），参数与网格都没变就直接用，省掉约 70 s、21–35 s
与约 3.5 min；变了（例如改了 `P.fieldMapX`，它不在那 35 项里，所以不会被 `stamp_guard`
拦住）就自动重算。想凭空强制重算：`run_refresh('force')`。

## 7 三条"读代码"路线

不知道从哪看起时，按下面三条线走一遍：

**路线 A：一条平面波的一生**
`params.m` → `acquire_pw.m`（发射）→ `das_pw.m`（成像）→ `stage_analysis.m` 的
`compound_rf`（复合）→ `to_db.m`（显示）。

**路线 B：一个指标怎么来的**
报告里的"横向分辨率 0.75 mm"：`metrics_resolution.m`（找峰值、取剖面、上采样、
找 −6 dB 交叉）→ `crossing_width.m`（插值定位）；数据由 `stage_analysis.m` 里
`R.P3.env(:,:,k)` 提供。

**路线 C：一张图怎么来的**
`make_figures.m` 的 F8 段：读 `R.P2.db(:,:,q)`（q=1 是 PW、q=2 是 C11）、统一 60 dB 色标、
1×3 子图排版（第三幅是单焦点）、`save_fig` 导出。

**读注释的约定**
每个函数开头都按同一套层次写：**链路位置**（输入从哪来、输出给谁）→ **原理**
（这一步在物理/数学上做了什么）→ **为什么这样做**（与替代做法的对比）→ **关键
取值与实测**（参数为什么是这个数，引用的数都来自实测并注明出处）→ **易错点**
（踩过的坑）。所以读一个陌生文件时，先读头注释就能知道它为什么存在。

如果需要快速建立整体印象，这五个文件的注释最密：`src/das_pw.m`（计算成像的核心）、
`config/params.m`（每个参数为什么取这个值）、`src/stage0_calib.m`（自检与时间零点）、
`src/stage_sigma.m`（噪声模型）、`src/stage_analysis.m`（复合与三个指标）。
约定与"注释里的数必须与代码一致"这条规矩写在 README 的「代码怎么读」一节。

## 8 常见修改场景

| 想改什么 | 改哪里 | 要不要重跑 |
|---|---|---|
| 平面波角度（个数/范围/间隔） | `params.m` 的 `P.angleStepDeg` 与 `P.angleIndex`；`P.compoundCounts` 同步 | **要重跑采集**（11 个角度约 8 分钟） |
| 接收 F 数 | `params.m` 的 `P.fNumber` | 要重跑采集（≈1 h） |
| 散射子数量/密度 | `params.m` 的 `P.nScatterers`、`P.phantomExtentX/P.phantomExtentZ` | 要重跑采集 |
| 囊肿个数/位置/大小 | `params.m` 的 `P.cystCenterX/P.cystCenterZ/P.cystRadius` | 要重跑 REM（约 10 分钟） |
| 噪声水平 | `params.m` 的 `P.pwSnrTargetDB` | 只需重跑 `stage_sigma` + `stage_noise`（几分钟） |
| 显示动态范围 | `params.m` 的 `P.displayRangeDB` | 只影响图，`run_refresh` |
| 指标定义 | `metrics_*.m` | `run_refresh`（不用重采集） |
| 加一张图 | `make_figures.m` 末尾照抄一段 + `save_fig` | `run_refresh` |

**改参数的铁律**：只改 `params.m`。采集中途改参数会让新旧数据混在一起，那是最难查的错误。

## 9 踩过的坑（以及为什么代码长成现在这样）

| 现象 | 原因 | 现在的处理 |
|---|---|---|
| 图像被斜着剪切，复合完全散焦 | DAS 少了 x1·sinα/c | 见 5.2.1；E0 用残差定量把关 |
| 点目标深度偏 1–2 mm | 时间零点没标定 | E0 逐角度标定 dt，峰值深度验证到 ±0.03 mm |
| 囊肿对比度明显偏高 | 只挖了 3 个囊肿（cystCenterX(k) 配 cystCenterZ(k)） | `cyst_centres.m` 统一算 3×3=9 个中心 |
| 合成声场里出现一条"窄条焦斑"（已废弃该图） | 只补了轴向相位，横向相位 x·sinα/c 还留着 | 该做法已删除，改为逐点成像验证（`psf_map.m`）；见报告归档 B13 |
| 合成声场增益只有 1.6（应为 ~11） | 每列都读到了第 1 列（线性索引少了列偏移） | `li = ... + col`，并注释说明（该段代码随后整体删除） |
| 轴向分辨率在 0.11–0.23 mm 之间乱跳 | 0.05 mm 网格对 0.19 mm 宽的包络太粗（−6 dB 以上只有 3—4 个点） | 测量前 8 倍 pchip 上采样；剩下的 0.005–0.017 mm 偏置随深度变化，已计入报告 5.5 节的读数不确定度 |
| CNR 几乎不随方法变化 | 囊内一黑，CNR 饱和在 0.7 | 报告里说明以对比度为主判据 |
| 0° 那一次的通道数据读不到（F6 报 "无法识别的字段 ch"） | 文件下标写死成 36（旧 71 角度集的 0°） | 一律用 `P.zeroAngleIndex`（11 角度时是 6） |
| 合成场的峰值落在 27 mm 而不是 30 mm（该图已废弃） | 那本来就是"只补一半延时"的残差，峰值位置没有物理意义 | 改为逐点成像；报告 5.3 与归档 B13 |

## 10 名词表

| 名称 | 含义 |
|---|---|
| PW | 单平面波（plane wave），n = 1 |
| C11 | 11 个角度（−10°…+10°，间隔 2°）的相干复合 |
| CPWC | Coherent Plane-Wave Compounding，相干平面波复合 |
| DAS | Delay-and-Sum，延时叠加波束形成 |
| PSF | 点扩散函数，点目标成像后的光斑 |
| F# | F 数 = 深度 / 孔径宽度；接收固定 1.75 |
| 合成孔径 | 用多个角度的发射"拼"出等效的大孔径 |
| 相干因子 γ | 角度间信号的相关程度；点目标 0.98–0.99，散斑约 0.25 |
| 采集帧率 | f_PRF / n，由序列推导，与机器无关，本文不作实验对比 |
| 算法处理帧率 | 1/t_frame，从通道数据算出一帧 B 模式的速度，E7 实测 |

## 11 复现步骤与耗时

```matlab
% 0) 环境：MATLAB R2024a + Field II（路径见 params.m 的 P.fieldIIPath）
% 1) 冒烟测试（约 2 分钟）—— 必须通过
run_test_p3

% 2) 核心实验（冷启动约 50 min，负载重时 ~95 min；数据已在时约 10 s，采集全部跳过）
%    E0 标定 → P3 点目标 → P1 散斑（11 角度 + 128 线）→ REM 囊肿
%    → 噪声 → 声场 → 分析
run_core
% 改了影响采集的参数后必须冷启动（否则会报“参数不一致”）：
% run_core('cold')

% 3) 收尾：声场 + 指标 + 逐点成像 + 图 F1–F14 + 表（约 10 s，不碰采集）
%    声场图与 PSF 图命中缓存时省掉，强制重算用 run_refresh('force')，约 35–50 s
run_refresh

% 若 run_core 在 P1 之后中断（REM/噪声还没采），改用下面这条，约 7 min：
% run_tail; make_fig_pointtargets
```

`run_refresh` 不碰采集，重算声场+指标+逐点成像并直接产出 F1–F14 与表。其中声场图（约 70 s，含 5 个亚样本平均）与逐点成像（21–35 s）是确定性计算，各自带输入指纹：参数与网格没变就直接用磁盘上的结果，所以常规一次刷新约 10 s；`run_refresh('force')` 强制重算时约 35–50 s。**日常复现只需要 `run_core` + `run_refresh` 两步**；`run_tail` 只在 `run_core` 于 P1 之后中断时才用（它比 `run_refresh` 多一层“缺什么采什么”的 REM/噪声采集；F13 由 `make_fig_pointtargets` 单独出，`run_refresh` 里已经调过）。

单次耗时参考（2 万散射子、128 通道）：

| 操作 | 耗时 |
|---|---|
| 一次平面波发射 + 波束形成 | ≈27 s |
| 一次聚焦发射 + 波束形成 | ≈17–28 s（独立接收句柄之后，见 B12） |
| 11 个角度 | ≈5 min |
| 128 条聚焦线 | ≈58 min |
| 声场（11 角度 × 2296 点） | ≈4 s |
| 逐点成像（165 个网格点 × 11 角度） | ≈21–35 s（命中指纹时 0 s） |
| 分析与出图 | ≈10 s（含 F1–F14 与表） |
